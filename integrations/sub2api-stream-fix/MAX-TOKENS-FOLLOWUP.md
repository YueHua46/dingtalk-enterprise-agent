# Explicit MAX_TOKENS without visible output

During the recovered real advertising task on October 14, production diagnostics reported valid wrapped frames, a candidate ending with `MAX_TOKENS`, and no malformed JSON or provider error frame. This establishes output-budget termination for those newly observed requests. It does not retrospectively establish the cause of earlier uninstrumented failures. The exact frame count must be taken from the saved log, not truncated terminal output.

The processor already translates `MAX_TOKENS` to Anthropic `stop_reason=max_tokens`. However, the compatibility session buffers events until text, thinking text, or a tool call appears. With no visible content, it discards valid stop/usage events at EOF and replaces them with retryable `empty_stream`. The existing Responses adapter can correctly emit `response.incomplete` with `incomplete_details.reason=max_output_tokens`; the session prevented it from seeing the terminal.

`sub2api-streamfix.1-max-tokens.patch` is the supplemental source patch deployed as **streamfix.2**, applied after `sub2api-v0.2.16-stream.patch`. It preserves an explicit no-content MAX_TOKENS terminal and usage through the existing adapter. It never invents a successful `response.completed`. It also adds numeric `prompt_tokens`, `candidate_tokens`, and `thought_tokens` to safe stream diagnostics. No output budget or upstream limit is changed. The previous streamfix.1 binary does not contain this follow-up; the active streamfix.2 binary and hash are recorded in README.

## Exact output budget path

`ForwardAsResponses` → `ResponsesToAnthropicRequest` → `convertClaudeMessagesToGeminiGenerateContent` → `convertClaudeGenerationConfig`.

An omitted `max_output_tokens` becomes `max_tokens=8192` in the shared Responses bridge and then `generationConfig.maxOutputTokens=8192`. An explicit positive request value is forwarded. The 64,000 clamp in `preserveChatCompletionTokenLimit` applies to explicit Chat Completions fields, not this Responses path. This Gemini converter omits Anthropic thinking configuration; mapped model variants can still apply their own thinking behavior. Whether hidden thinking consumed the actual failing request's budget requires provider usage counts; MAX_TOKENS alone does not prove that breakdown.

Repeatedly sending the same request with the same budget after this deterministic terminal cannot be treated as an ordinary transient empty-stream retry. A bounded, explicitly configured output budget can be evaluated with a same-context comparison, with no automatic increase beyond a verified provider limit.
