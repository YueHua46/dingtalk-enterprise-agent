## DWS 授权失败引导兜底（dingtalk-enterprise-agent）

- 线上现象：模型调用 DWS 工具时设备授权进程 exit code 3，未产出链接，原始错误直接透传给模型，模型只能让用户"先完成环境授权"，没有可操作引导。
- 根因分层：`ensureAuthorization`（task-orchestrator.ts）只处理 `DWS_OAUTH_REQUIRED`，授权"发起失败"落入普通失败分支透传。
- 修改：
  - `src/dws-broker.ts`：导出 `DWS_AUTH_INIT_FAILED` 标记；`beginDeviceAuthorization` 三处 reject（spawn error / exit 无链接 / 20s 超时）统一带该前缀 + 子进程输出尾部 400 字符（做了 token 类信息脱敏），便于定位 code 3 真实原因。
  - `src/task-orchestrator.ts`：`ensureAuthorization` 重写——发起授权自动重试一次（间隔 1s）；发起/私聊发送失败时任务状态从 `waiting_oauth` 回退 `running`，审计 `oauth.init_failed`；授权 completion 失败审计 `oauth.completion_failed`；`handleCodexRequest` catch 新增 `DWS_AUTH_INIT_FAILED` → 结构化引导文案（告知用户稍后重发任务、勿自行执行授权命令、反复出现找管理员查 CLI/DWS_CONFIG_DIR/OAuth 配置），授权超时单列引导。
  - `userFacingTaskError` 增加 `DWS_AUTH_INIT_FAILED` → "授权服务暂时不可用，请稍后重试。"
  - 测试：orchestrator +2（重试后成功续跑 / 两次失败返回引导而非原始错误），dws-broker +1（init 失败错误带子进程诊断）。66/66 通过，tsc 编译通过。
- **根因已实锤（18:22 前后）**：部署就在用户本机 Windows Docker Desktop（compose 项目 dingtalk-enterprise-agent，gateway-1 :8080）。在容器内复现：`dws auth login --device --profile <corpId>:<userId>` 对未注册 Profile 报 `{"category":"validation","code":3,"message":"profile not found"}`——CLI 的 `--profile` 只接受已注册 Profile；首次授权必须不带 `--profile`（bot 登录脚本 scripts/dws-bot-login.mjs 就是这么写的，实测能产出授权码+链接）。
- **修复**：dws-broker.ts 新增 `profileRegistered()`（查 profile list），`buildDeviceAuthorizationArgs(user, registeredProfile)`——首次不带 --profile、重授权才带；身份绑定仍由 pollAuthorization 的 status()+sameIdentity 在授权后校验。task-orchestrator catch 增加 identity mismatch 引导分支。operations.md 员工 Profile 流程描述已更新。测试 67/67。
- 部署：docker compose build gateway 后 up -d gateway（旧镜像跑的是未修复代码）。
- **第二次线上失败（18:27）**：链接已产出（第一步修复生效），但机器人私聊发送失败——`dws chat +messages-send --as bot --profile <DWS_BOT_PROFILE>` 报错。排查发现当前 `dingtalk-enterprise-agent_dws-data` 卷是 17:37 新建的空卷；旧授权数据在 **`f_dws-data`** 卷（之前项目目录叫 "f"），含盛喜的 Profile 和 Keychain。用户明确拒绝迁移旧数据、也拒绝手动跑 bot 授权脚本。
- **需求最终对齐**：授权引导必须完全发生在钉钉内——任何用户首次触发 DWS 操作且其 OAuth token 不存在时，机器人自动私聊该用户本人设备授权链接，每人用各自 token，给各部门用时不依赖管理员个人授权。
- **最终修复（18:38 部署）**：`DingTalkNativeCardBroker.sendRobotDirectMessage`——机器人单聊走钉钉原生 `robot/oToMessages/batchSend`（msgKey=sampleMarkdown，仅用 DINGTALK_CLIENT_ID/SECRET 应用凭证）；main.ts `sendDirect` 原生优先、DWS_BOT_PROFILE 仅作降级；safeDeliveryError 增加 user_code 脱敏。**DWS_BOT_PROFILE 变为可选**（README/operations.md 已更新）。曾误拷旧卷数据到新卷，已按用户要求清除恢复空卷。测试 68/68。
