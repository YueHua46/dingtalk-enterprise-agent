# 证据、优先级与输出

## 结论分级

| 等级 | 何时使用 | 写法 |
|---|---|---|
| 数据事实 | 报表直接给出，且口径清楚 | “该 ASIN 销售额从 X 降至 Y” |
| 计算结果 | 由可核对的公式和原始数值推出 | “下降 Z%，贡献总降幅约 N%” |
| 高可信推断 | 时间、对象和多个独立信号一致，替代解释已核查 | “缺货很可能是主要原因，依据是……” |
| 待验证假设 | 仅有相关迹象或缺少关键字段 | “可能与流量结构有关，需要……验证” |
| 无法判断 | 核心数据缺失或冲突 | “目前无法判定原因” |

不要把相关性写成因果性；没有对照数据时不要声称“提升了多少销量”。若两个报表口径冲突，先说明差异和选择依据。

## 优先级

优先处理“影响金额/销量大、时间紧、证据强、行动可执行”的问题。能计算时给具体规模；不能计算时明确用定性排序。紧急缺货或不可购买状态可能优先于金额略高但可等待的问题。把“建议核查”“可立即人工处理”“执行需确认”区分清楚。

## 默认回复结构

根据用户问题压缩或扩展，不要求固定长报告。

1. **结论**：一句话说经营结果和最重要的原因或待验证点。
2. **范围与口径**：店铺/站点、时间窗、数据截至日、来源；币种与关键限制。
3. **关键证据**：当前值、基线、差额/比例；贡献最大的 ASIN/SKU；关键因果链上的支持与反证。
4. **原因排序**：每项标“已证实 / 高可信推断 / 待验证 / 无法判断”，说明为什么。
5. **下一步**：1–3 项按影响和紧急程度排序的行动；需要更多数据时说明要查哪张报表或哪个字段。

对用户只问一个指标的情况，直接回答数值、范围和口径即可，不强行生成完整诊断。对经营周报或完整体检，可增加销售、流量/CVR、广告、库存、利润分节及异常清单，但只展示已验证的数据。
