# 数据口径与最小契约

分析时把每个数据集记录为：来源、报表名/工具、查询时间、店铺、站点、时区、币种、开始/结束日期、数据更新时间、粒度、维度、字段原名与定义。只在相同口径上比较。不要把广告归因销售额与店铺总销售额相加。

## 核心概念

| 概念 | 所需定义或计算 | 常见误区 |
|---|---|---|
| 销售额 | 确认是订单销售额、付款额、发货额还是净销售额；记录退款/税/运费是否包含 | 不同报表的销售额直接相减 |
| 订单、销量 | 订单数与件数分开；明确取消单和退款单处理 | 把件数当订单数 |
| 流量 | Session、访客数、Page View 分开；先核对 ASIN/父体/子体维度 | Page View 除以订单得到“转化率” |
| 转化率 | 同口径订单数或销量 ÷ 同口径 Session；优先沿用报表明确给出的 CVR 定义 | 不同时间窗、不同 ASIN 层级混除 |
| 客单价/均价 | 订单销售额 ÷ 订单数，或销售额 ÷ 销量；标明是哪一种 | 把客单价变化直接归因于调价 |
| 广告 | 分清花费、广告归因销售、ACOS、TACOS、展示/点击；核对归因窗口 | 广告销售当自然销售，或跨归因窗口对比 |
| 库存 | 分清可售、预留、在途、不可售、总库存；确认 FBA/FBM | 用总库存算可售天数 |
| 利润 | 收入、退款、平台费、广告、采购成本、物流、仓储、税及其他费用的覆盖范围 | 缺采购成本仍称“净利润” |

## 对齐检查

1. **时间**：使用站点/报表时区；当前周期与基线等长且均已完整。若存在约 1–2 天数据延迟，按来源实际刷新时间截断两期；不要把 Amazon 官方连接器的延迟假设直接套给领星。
2. **实体**：同一店铺、marketplace、SKU/ASIN 映射版本。父体聚合时避免与子体重复计数；多 SKU 对同一 ASIN 时说明聚合方式。
3. **数值**：币种转换只在明确汇率与日期时进行；比率由分子分母重新计算，不对比率求简单平均。零基线时给绝对变化，不报无穷大百分比。
4. **覆盖**：分页、筛选条件和总行数要核对；检查缺失日期、重复记录、退款回写、异步报表滞后。空结果可调整一次合理条件，仍为空就如实报告。
5. **来源冲突**：展示两种口径及差额，选择与当前问题最匹配的一种，不能悄悄拼接。

最小可用数据可以只有两期的销售额与销量；此时可以量化变化及 SKU 贡献，但不能断言流量、转化或广告是原因。缺少 Session 时不要计算 CVR；缺少完整成本时只谈已知费用后的贡献利润。
