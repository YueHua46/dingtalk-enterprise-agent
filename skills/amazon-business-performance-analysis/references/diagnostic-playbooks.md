# 经营诊断方法

先回答用户的问题，再展开相关分支。每个分支都要给出数值变化、主要 ASIN/SKU 和反证检查；只把数据支持的信号升级为结论。

## 销售变化

1. 用同口径等长周期计算销售额、订单数、销量的当前值、基线与差额；按 ASIN/SKU 排序，找出对总差额贡献最大的正负项。
2. 对主要负贡献 ASIN，拆成流量、转化与每单/每件销售额。粗略恒等式是 `订单销售额 ≈ Session × 订单/Session × 销售额/订单`，前提是三者同一口径；不满足时分别描述，不能强行相乘。
3. 流量下降时检查广告曝光/点击与花费、自然搜索可见性、Listing 可搜索性、促销结束与季节性；转化下降时检查缺货/配送、Listing 可购买性、评价、价格/优惠变化以及流量结构；均价下降时检查折扣、变体组合、退货口径。
4. 事件发生时间应先于或同时于指标变化，并且影响 ASIN 对得上，才可说“支持某原因”。多项变化同现时按证据强度排序；无法拆分交互效应时不报精确归因比例。

## 流量与转化

- 同时看绝对 Session 与占比，按 ASIN、渠道和设备拆分；结构变化可能让整体 CVR 下滑，即使每个细分组未恶化。
- 比较相同星期结构和完整周期；Prime Day、黑五、促销或新品期应单独标注，不直接与普通周作因果比较。
- 仅有 Page View 时讨论浏览量，不称之为 Session，也不从它推算 Amazon 的 Unit Session Percentage。

## 广告与自然销售

- 以广告花费、归因销售和店铺总销售分别报告；ACOS=`花费/广告归因销售`，TACOS=`花费/店铺总销售`，分母为零则标不可计算。
- 广告订单与自然订单若无可靠去重/拆分，不计算“自然销售=总销售−广告销售”。广告指标可解释投放表现，但不能单独证明其造成自然排名变化。
- 需要搜索词层面的否词或出价判断时，转到已安装的专项搜索词 Skill，并遵守其样本量要求。

## 利润与费用

- 先列销售额 → 退款/折扣 → 平台费用 → 广告 → 商品与头程成本 → 其他已知费用；给出每层金额和数据覆盖率。
- 只有费用齐全且期间匹配时才称“净利润/净利率”；否则称“已知费用后利润”或“贡献利润”，同时列缺项。
- 重点看利润金额与利润率是否同步变化，按 ASIN/SKU 找驱动项；不要套用外部所谓类目平均利润率作为事实。

## Listing 与账户异常

当销量骤降且流量、CVR 或库存单项解释不足时，检查是否有不可购买、搜索受限、主图/属性错误、配送变化或账户健康事件。领星没有状态数据时标为待核查，不把“可能被抑制”写成已发生。前台体验问题可交给 `zach-listing-health-checker`。
