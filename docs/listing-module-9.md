# 模块 9：Word、Excel 与原会话交付

本模块生成运营参考稿，不设置审核人或审批状态，不调用 Amazon 上传接口。模块 10 尚未注册 Listing 动态工具和专用 Skill，因此本模块完成不代表运营已经能在生产对话中直接使用整个流程。

## 输入和交付内容

`buildListingExport(scope, version, currentContext, { previous?, research? })` 只由宿主调用。输入是模块 8 保存的完整版本及当前宿主事实、规划、规则、校验策略；不接受模型提供的可复制标记。版本内容哈希、身份、原会话、事实与规划完整快照均检查。事实或规划改变需要先完成修订；仅规则或受控表达策略变化可以在导出时直接重新校验。上一版必须是当前版本的直接父版本。

默认形成一份共同的数据视图，供摘要、Word 和 Excel 使用：

- 原页面、上一版草稿、当前参考稿、可复制文案分开列示。原页面只读取本次调研中有原始证据的本品 ASIN 标题和五点，标为未经独立核实；缺少描述和后台搜索词时明确标记，绝不把上一版草稿伪装成页面原文。
- 新品显示“产品事实与生成依据”，没有原页面。每条事实保留完整限定条件、资料引用、摘录和来源可信度，中文标签方便运营阅读。
- 修改原因标为生成建议。代码检查结果、待核实事项和产品依据分别呈现；产品依据不使用竞品能力。
- 竞品记录核对当前任务范围、原始证据哈希和产品快照，包含 ASIN、选择原因、公开价格/评分/评论数、页面 URL、采集时间和局限。没有记录时明确说明缺口，不编造销量或评论分析。
- 钉钉摘要包含修改方向、可复制字段数量和核实事项。Word 逐字段列示，避免宽表挤压正文；Excel 分工作表，保留原文、上一版和出处，冻结字段/表头，支持筛选。

导出重新运行模块 7 的纯代码校验。硬错误和待核实字段在“可复制文案”区留空，参考稿仍可查看。平台合规始终不宣称完全确定。当前真实配置尚待核实，虚构摄像头样例的可复制字段为 0/8；测试中的已核实策略仅用于验证正向分支，未修改生产规则。

## 文件生成和安全

`file-skills/listing_export.py` 是固定程序，无模型、网络、shell 或业务工具调用。生产隔离文件服务已有 python-docx/openpyxl，未安装 artifact-tool，复用现有库，不增加业务运行依赖。每个 Excel 单元格显式写成字符串，`=`、`+`、`-`、`@` 和类似外部指令不会变成公式；不创建外部链接关系或宏。

导出视图使用严格 schema，限制单元格、行数、整体字节数并拒绝非法 XML 控制字符。HTTP 按字节限额读取，跨请求分块保留完整 UTF-8 中文；非法 UTF-8 拒绝处理，不能悄悄改变产品资料。资源限额超出时失败，不静默截断产品事实。文件名由渲染器版本和完整交付视图哈希产生，ZIP 与 Office 元数据时间规范化；同一版本和视图重复生成字节一致。输出采用排他硬链接，已存在但内容不同则报冲突，不覆盖历史成果。

新增固定 `/tasks/:taskId/listing-export` 文件服务接口，沿用宿主密钥认证、每任务 UID、受限目录和子进程超时。正文是 JSON 数据，不拼成执行代码。返回经过检查的文件名，而不是绝对路径，兼容现有 `outputs/inspect` 契约。

宿主 `deliverListingFiles` 校验当前用户与原会话后复用 `artifact.submit` 的公共提交内部实现。文件下载后检查大小、哈希、实际类型并扫描，再按 `task.request.user` 和 `task.request.surface` 投递；回执、幂等键和未知结果保护沿用已有持久化记录。已完成的发送不会重复；结果未知不盲目重发。取消在渲染前后、文件间、扫描后和发送前检查；已经开始的远端发送不能承诺撤销，沿用宿主结果未知处理。

## 默认报告样式

渲染器 `listing-report-design-v2` 采用深蓝、灰白配色，暖色用于需要核实的提示。Word 首页展示交付概览、修改方向和核实摘要；正文左右对照原页面或上一版与当前稿，新增及替换文字以蓝色粗体标注，保留完整原文与依据。重复检查消息按内容集中到附录，并保留涉及字段；原字段检查未出现在摘要时仍补入附录。产品事实和版本短表尽量完整分页，长表按行分页并重复表头，页脚显示页码。视觉标注不会修改文案、解除复制限制或虚构公司标识。

Excel 保留全部字段和原有单元格位置，合并标题行，冻结字段及表头，使用交替底色。当前稿以蓝色突出；可复制列留空时使用暖色提示。修改原因、出处和检查列默认可见，允许折叠，保留各列宽度；所有内容仍按文本写入。模板版本参与文件名，样式升级不会覆盖旧模板文件。

## 样例和验收

样例产品是虚构 ExampleBrand C1。文案基于模块 6 的已有真实模型记录和模块 8 的固定 mock 修订，不是新增真实模型效果评估，也未使用公司 DWS 资料或给真实钉钉成员发送消息。

- `examples/listing/listing-export-sample.docx`：7 页报告，逐页视觉检查。
- `examples/listing/listing-export-sample.xlsx`：5 个工作表，artifact-tool 导入、关键范围检查、公式错误检查及每表渲染检查。桌面捆绑运行时没有 LibreOffice；Word 使用应用生产文件服务的 LibreOffice 渲染，未使用用户桌面安装的软件。
- `examples/listing/export-version-sample.json`：完整版本及父版本，供固定回归使用。
- `output/listing/export/summary.txt`：钉钉摘要示例。
- `output/listing/export/worker-results.json`：新代码在临时隔离 HTTP 服务中的真实认证、schema、重复生成、检查/下载哈希测试。临时服务和文件已清理，未部署覆盖现有服务。
- `output/listing/export/scan-results.json`：两个文件的真实 ClamAV 扫描均为 `stream: OK`。

本模块新增 30 项 TypeScript 测试和 11 项 Python 文件测试。覆盖出处、篡改、当前规则重校验、原 ASIN 与上一版区分、可复制正反分支、公式注入、文件内容一致性、不可覆盖输出、样式版本隔离、改动高亮、分组列宽、检查消息去重及字段关联、原会话交付、当前用户身份、哈希/病毒拒绝、幂等、未知结果和取消。发送使用 mock；真实钉钉端到端对话及文件到达验证留在模块 10，与本次真实文件/扫描/工作服务测试分别记录。

```powershell
npm run build
npm test
node scripts/listing-export-smoke.mjs
node scripts/listing-export-render-smoke.mjs --visual
node scripts/listing-export-worker-smoke.mjs
node scripts/listing-export-scan-smoke.mjs
```

后三个 smoke 命令需要现有 Docker 文件服务、gateway 和 ClamAV。使用唯一临时任务根目录，不读凭证、不访问 DWS；不会修改生产任务或发布新镜像。模块 10 接入、评估及真实钉钉验收见 docs/listing-module-10.md。

样式升级后验收：npm run build 通过；npm test 为 49 个测试文件、597 项测试全部通过；独立 Python 文件测试 11 项通过。真实隔离文件服务的认证、schema、重复生成及检查/下载校验通过，两个最终样例的 ClamAV 扫描均为 OK。
