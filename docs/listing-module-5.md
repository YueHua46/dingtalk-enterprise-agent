# 模块 5：关键词、评论关注点与卖点规划

入口 `buildListingContentPlan(factBook, research, policy)` 是纯代码函数，不调用模型或业务工具。输入来自模块 2 与 4，必须属于同一用户、任务、会话。输出仍是生成前的规划，不是最终 Listing，不代表平台合规检查通过。

`config/listing-planning.json` 保存内部词表、主题及分配预算；这些是保守文案策略，不是 Amazon 官方限制。平台规则仍由模块 3 配置负责。关键词来自运营、真实搜索请求或已确认相关的竞品字段；保留出处，搜索量始终为 null，不把排名或评论数换算为搜索量。

只有受控词表匹配本品可用事实的关键词才自动分配到标题、五点或描述/搜索词候选区。未知词、无依据功能及页面来源词保留为核实项。否定标记按整个事实值保守阻断，因此“支持 Wi-Fi，不支持 5GHz”可能暂不分配 wifi camera，但完整事实仍保留供后续生成表达。字面匹配不等于完整语义验证；最终声明约束及文案校验由模块 6、7 实现。

评论按配置字面词统计提及主题，不判断情绪、差评原因、因果或全体买家的比例。相同 review_id 与规范化正文跨竞品去重，保留各来源引用；没有有效样本时输出缺口。样本可以建议说明安装、订阅等本品已有事实；不能把竞品功能、评论愿望或“解决竞品痛点”变成本品卖点。

卖点按属性保留原值、完整出处、限定条件及逐条 trust。冲突/待核实事实排除；页面事实明确标注。没有跨属性推断性能、保证或优于竞品的结论。外部文本即使含有工具调用指令，也仅保存在引用数据中；本函数没有执行接口。证据哈希、工具、站点、解析字段与快照一致性均检查；哈希提供一致性检查，不作为远程来源身份认证。

## 验收和样例

`npm test -- tests/listing-planning.test.ts` 覆盖事实支持、否定、数字词边界、费用/排除项、评论去重、无评论、注入数据、跨会话拒绝、快照篡改、未知关键词、确定性及无输入变更。`npm run build` 后执行 `node scripts/listing-planning-sample.mjs` 生成 `examples/listing/planning-sample.json`，全部为虚构 mock 数据。

`node scripts/listing-research-smoke.mjs` 在已有网关容器内只读查询公开 Amazon 数据，验证事实→调研→规划衔接。真实评论若为空则不产生洞察，不用 mock 补成真实结果。它不是完整钉钉端到端验收，也不涉及上传、发送消息或 DWS 身份替代。

模块 6 的结构化生成见 `docs/listing-module-6.md`。模块 7–10 尚未实现；纯代码校验、修订、文件投递和完整评估待后续模块接入。
