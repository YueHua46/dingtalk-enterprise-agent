# 企业知识检索

实现入口：`knowledge.search`、`knowledge.read`、`knowledge.lookup_product`、`knowledge.status`。
工具输入使用严格白名单，员工身份由任务上下文注入。目录、访问状态及当前版本按企业和员工保存。知识内容作为证据进入现有交付核验链路，群任务返回原群。

## 配置与部署顺序

`KNOWLEDGE_ENABLED=false` 为默认值；`KNOWLEDGE_TEST_USERS` 仅用于真实验收账号，值为逗号分隔的 `corpId:userId`。`EMBEDDING_*` 配置仅在宿主；文件 worker 不保存模型密钥。1024 维和批量上限 20 在宿主强制校验。

1. 用现有备份服务生成 PostgreSQL 自定义格式备份，在独立 PostgreSQL 17 实例实际执行 `pg_restore --exit-on-error`。
2. 构建 `Dockerfile.postgres`。基础镜像保持 `postgres:17-alpine`，pgvector 版本固定 0.8.6，数据目录保持 `/var/lib/postgresql/data`。
3. 数据库服务切换到该镜像并确认健康。不要把现有数据卷挂到验收数据库，不删除数据卷。
4. 构建 gateway 和 file-worker；migration 011 增加知识结构，015 增加按员工和来源节点隔离的图片识别检查点。文件 worker 通过固定 `knowledge_parse.py` 入口以独立任务 UID 解码。模型调用留在宿主。
5. 首先配置验收账号，完成下述真实验收；全部标准通过后才设 `KNOWLEDGE_ENABLED=true`。

已授权且未停用的员工会在启用后自动加入同步。独立 BullMQ 队列无自动失败重放，数据库 advisory lock 防止同员工重复扫描；默认每 15 分钟安排一次。前台 DWS 调用优先于后台等待请求，单进程业务读取并发为 2。当前部署按单 gateway 设计，多 gateway 部署仍需分布式 DWS 请求限流，不能把单进程限制当作跨实例限制。

个人授权失效时暂停同步。只有该员工完成宿主 OAuth 流程，或同身份的实时正文读取成功，才恢复暂停的同步；定时任务不会改用其他员工继续读取。

## 数据与更新

### 首次全量入库

启动独立验收 PostgreSQL 和文件 worker 后，运行 `npm run knowledge:ingest:all`。入口只选择唯一 `isOrgCurrent` 员工 profile，重新完成全库目录扫描，再通过流水线并行处理文字与图片：2 个文字任务提交版本后，将该资源加入图片队列，2 个图片文档任务使用共享的 50 路识别池，不等待全库文字完成。两条路径在同一宿主进程中共享 DWS 读取上限 2。文字失败的资源不再自动重复进入图片任务。读取钉钉资源均显式绑定该员工 profile，不修改钉钉文档。

此入口写入已有的独立知识验收库 15432；生产开关仍保持关闭，不因批量入库提前向员工开放。进度在 `output/knowledge-full-ingestion/progress.json`，阶段 `text_and_images` 表示两条处理路径同时运行，分别保存文字与图片计数、每个资源的版本、质量缺口和失败代码。中断后重跑同一命令，当前解析器及 embedding 模型下已完成的版本会跳过；图片未完成的资源仍进入图片队列。授权失败暂停本次运行，不能改用其他 profile。数据将用于后续部署验收，不能把该入口运行中等同于生产同步已经启用。

`--retry-failed` 选择失败、未处理及已提交文字但图片尚未完成的资源，不只看 ready/stale 单个状态，防止中断丢失内存中的图片队列。`--upgrade-parser` 选择解析器或 embedding 模型需要升级的资源；两种模式都先完成目录检查，或显式用 `--resume` 复用仍在有效期内的完整目录。新版本成功处理前不能把旧解析器资源计入升级完成率。

图片识别按用户要求设置 `KNOWLEDGE_VISION_CONCURRENCY=50`，文档读取仍为并发 2；同文档图片并行处理，保留原始顺序和位置。宿主内多个知识模型实例共享同域名/模型的识别并发池，总在途调用不超过 50；失败时停止继续提交该文档的新图片并等待在途调用结束。此限制是单宿主进程的；多宿主部署需要分布式限流。批量任务重启可用 `node --env-file=.env scripts/knowledge-ingest-all.mjs --resume` 复用同员工最近 6 小时已完成的完整目录快照，已入库版本跳过，之后仍须正常定时重新发现目录。该模式不声称目录是当前实时快照。

全量目录分页必须完成。`hasChildren` 文件同样递归，未支持正文的导图不阻塞子文档。未完成目录不标记缺席，明确缺席、删除和权限拒绝分别保存。旧版本在解析失败时保留，但正文交付前必须重新读取，验证失败不返回缓存。

工作簿通过 DWS 正式导出获取全部工作表，保留真实行号、单元格及合并范围。参数段重复明确型号，避免跨型号拼接。历史订单集中目录“信息表”只登记目录。PDF 保留页码及区域；宽页面分面板识别。图片先由 worker 本地 OCR 过滤凭据所在行，再交给现有多模态模型。普通修改密码流程仍可保留，凭据目录和字段不送模型。

新内容解析和 embedding 全部完成后事务切换版本。图片识别资产存在知识数据库，随版本清理；失效版本 30 天后删除。临时下载目录在任务结束时清理。知识目录和数据卷独立于聊天附件清理。

查询发现新版本时，可用刚读取的当前正文回答，引用版本为 `live:<内容指纹>`；独立资源刷新队列随后准备图片识别和向量，不等待全库扫描。当前正文读取失败则返回覆盖缺口。解析器或 embedding 模型升级同样触发重新入库。

解析器 `knowledge-v3` 使用完整 manifest 和分页图片协议：目录式解析保留全部图片摘要和位置，每批最多 4 个图片区域，分别执行本地凭据遮盖后传回宿主。宿主逐批核验源指纹、数量、游标、图片摘要和位置，全部识别及向量化完成后才切换当前版本。单份文档不再受旧版整份 100 张图片上限影响，180 秒 worker 限制和 32 MB 单次输出预算仍保留。每个任务固定解析程序快照，避免一次分页过程中代码变更导致混合解析。表格按实际有值单元格处理，保留原始坐标，避免空白格式扩大读取矩形；实际单元格、解压大小、像素及 PDF 页数预算仍检查。

知识源通过独立的流式输入协议接收，`KNOWLEDGE_MAX_SOURCE_BYTES` 默认且最高 256 MiB；普通任务附件继续使用 `MEDIA_MAX_BYTES`。宿主逐块完成同一次 ClamAV 安全扫描和文件 SHA-256 校验，再流式上传；worker 同样按累计字节上限写入，宿主校验接收大小和摘要。ClamAV 传输、单文件及总扫描预算与此协议配套，超出扫描预算的文件拒绝入库，不把未完整扫描当作安全。原先 55 MiB 和 134 MiB 的说明书不再需要放宽普通附件通道。

成功图片结果保存至 `knowledge_image_results`，复用键包含员工、企业、来源节点、当前图片内容和模型/提示版本；只有以同员工身份重新读取并验证当前图片后才使用检查点。同一图片的并发调用去重，失败不缓存，检查点 30 天未使用即清理。图片结果复用不是权限证据。502/503/504、429 及明确可重试的连接错误最多尝试 3 次，遵守 Retry-After，过长或无法解释的服务器等待时间留待之后调度，禁止提前重试。权限拒绝、超时、无效模型输出和解析异常保留明确状态，不盲目重发。

检索采用中文二元词元、完整型号词元及精确向量召回，各 30 条，RRF 合并；最多 5 个来源、10 个片段。SOP 补取流程并显式报告展开范围是否完整。后续任务重新验证依赖资源，失效时创建新模型上下文，重置原会话历史截点和旧证据。

配置 `RERANK_MODEL=qwen3.7-text-rerank` 后，语义搜索增加重排序。域名和密钥复用 `EMBEDDING_BASE_URL`/`EMBEDDING_API_KEY`；按百炼官方协议使用同域名的 `/api/v1/services/rerank/text-rerank/text-rerank` 路径。RRF 召回后，先以当前员工身份核验最多 5 个来源，去重并将最多 60 个当前可读片段送入 rerank；每请求累计 UTF-8 字节预算 100000（包含重复 query）以约束输入。返回索引、数量和有限分数全部校验，不使用服务返回的正文替换来源证据。

输出 `ranking` 标记实际使用的排序方式、模型、候选数和状态。重排失败显式标记 `fallback`，返回原有 RRF 顺序的已核验片段；不重试失败的模型调用或同次查询中核验失败的来源。精确型号参数查询继续使用结构化参数记录，不做语义改排。rerank 仅作用于查询，无需重新生成向量，全量入库不受影响。运行 `npm run test:knowledge:rerank` 可验证真实模型和 DWS 核验搜索链路。

当前解析器版本为 `knowledge-v4`。在上述 v3 协议基础上，凭据 OCR 按全宽、最大400原图像素高、64像素重叠区域处理，保持原先分辨率策略，并映射回原图坐标再遮盖。所有区域共享单图90秒预算，任一失败拒绝整图输出。白板 hetu 卡片同样保留待识别图片标记，须经正式导出核验。此前版本通过 `--upgrade-parser` 重新处理，不仅修改版本标签。模型拒绝仅记录有界供应商错误码及请求标识，不记录错误正文、输入或凭据。

`knowledge-v5` 将普通在线文档图片改为读取当前员工完整 JSONML 的真实 resourceId，经 `doc +media-download` 逐图下载、验证返回的节点/资源/大小及 verified，再安全扫描和 worker 解码。保持所有原始 block 位置；全部图片核验后才发送识别模型，任一缺失拒绝该次版本。绝不跟随 src 或临时 OSS 地址。普通图片不再依赖整份 PDF 转换；hetu 白板仍须正式渲染导出并保留失败状态。导出成功而 OSS NoSuchKey 明确分类为导出对象缺失，保存已返回的任务ID与不可重试语义，不误认为OCR问题。

## 验收与限制

运行 `npm run build`、`npm test`。真实读取和模型冒烟使用 `node --env-file=.env scripts/knowledge-live-smoke.mjs`；该脚本只连接独立验收数据库 15432 和 worker 18081，不修改生产钉钉资源。`--skip-catalog` 用于目录已完整扫描后的解析或检索修复复测。

冒烟结果保存在 `output/knowledge-acceptance-2026-09-30/`。参数题集来自真实 DWS 工作簿，不能用它替代完整 SOP、FAQ、图片、跨语言、更新和权限验收，也不能把数据库隔离测试替代两个员工真实授权测试。

尚未完成的验收不能通过功能开关绕过：全量核心正文解析率 95%、混合题集证据命中率 90%、10 个真实并发问答、专用验收文档更新 20 分钟，以及第二个独立授权员工的撤权和原群投递测试。用户在 2026-09-30 明确选择保留当前问答模型并先接受较慢响应，本轮不再把 P95 30 秒作为上线门槛，但仍测量并报告真实延迟。钉钉资源增删改必须由宿主在验收原会话发送确认卡，不能从脚本自造用户同意。

独立验收服务为 `rag-postgres-acceptance`（15432）、`rag-worker-acceptance`（18081）、`rag-redis-acceptance`（16379）和 `rag-clamav-acceptance`（13310）。批量入库和修复复验使用此扫描器，原生产扫描器不变更。停止后可用 `docker start` 恢复上述已有验收服务。它们不是生产服务。详细实际结果和尚未通过的项目见 `output/knowledge-acceptance-2026-09-30/report.md`。

当前指标包括模型 HTTP 成功调用数、检索工具耗时、来源失败次数、按状态统计的资源覆盖、扫描年龄及最近扫描耗时。逐资源错误保存在用户范围内的状态接口。检索工具耗时不能当作最终答案端到端耗时。

关闭 `KNOWLEDGE_ENABLED` 并清空测试账号即可停止新的知识工具使用；原有 DWS 工具继续工作。关闭前应等待同步队列正在执行的扫描结束或停止知识 worker。脑图正文、多维表记录、旧 Office 转换、视频转写留待后续阶段。

knowledge-v6 增加 Word 导入自包含 SVG 正文字节解析：严格base64/8MiB输入，沿用安全扫描和任务快照，隔离worker以MuPDF完整2倍渲染并执行区域OCR遮盖，禁止外部资源/活动内容，保留block及图形内容摘要。普通媒体继续使用正式资源下载，不访问任意网络src。两份真实源扫描/渲染/OCR通过，但模型复验仍返回503，未完成识别和向量激活；v5全量批次已保存进度后停止，不把代码版本等同运行覆盖率。

在线文档PDF导出通过migration016的knowledge_exports保存员工、来源节点、完整JSONML指纹及任务状态。调用首次导出前持久登记，崩溃或任务结果未知时禁止重新提交；错误中的实际jobId保存后仅调用正式+export-get恢复。成功文件必须完成源版本回读、大小校验和安全扫描，才写入独立知识目录exports；后续以同员工完整源读取及版本核验、文件摘要/大小核验、重新安全扫描复用，不授予缓存访问权限。数据库导出锁避免并发重复提交和清理期间读取冲突。

历史job缺少导出前指纹时以source_hash=NULL登记，保留明确KNOWLEDGE_EXPORT_SOURCE_UNBOUND缺口，不猜绑定、重提交或以旧正文版本替代证据。成功回执未发布任务字段时不猜jobId，保留已验证文件；文件丢失且没有已知任务时报告结果未知。无有效版本引用的文件30天未使用后清理，任务账本保留用于防重提。数据库及文件测试不能替代真实导出成功验收。

`DWS_NO_PROXY` 可配置经核验能够直接连接的精确主机名，以逗号分隔；默认空。宿主只在DWS子进程中合并既有NO_PROXY/no_proxy，不移除HTTP_PROXY/HTTPS_PROXY，也不改变模型调用环境。当前验收主机的本地7897代理曾对mcp.dingtalk.com出现TLS握手超时，直连对照通过，因此本地配置加入该主机。运行中进程仍保持启动配置，新规则在下次启动加载；真实授权/元信息通过不等于整份导出或入库通过，不增加失败任务的自动重试。

Embedding 403通过migration017的knowledge_embedding_rejections持久保存员工/来源节点、模型、输入指纹及有限供应商code/requestId。所有资源索引入口（常规同步、查询触发后台刷新、全量正文、真实解析复验与入库冒烟）经KnowledgeStore.embedResource核验并以员工/节点锁防并发重发。同一资源未解决的拒绝不会因进程重启、解析器升级、模型或正文变化自动解除；正文和供应商响应不保存，拒绝不是钉钉撤权，不影响其他员工或节点。通用查询向量没有关联来源节点，仍沿用模型请求的有限重试规则。

历史拒绝输入指纹未记录时保存NULL，不猜输入或供应商原因；三份已有真实403已从原始v3进度导入，仅验证数据库guard不会调用模型，不能宣称来源/模型恢复或入库通过。该表不随30天缓存清理自动删除；供应商问题处理和明确核验之前，不提供自动解除/重试路径。scripts/knowledge-embedding-guard-smoke.mjs是实际PG持久/并发测试，供应商回调为fixture；scripts/knowledge-embedding-legacy-guard.mjs只导入历史证据并验证防重提，不发送业务内容。迁移目前只应用独立验收库，生产仍关闭。

表格整簿导出通过migration018 knowledge_sheet_exports和KnowledgeSheetExport持久记录员工/来源节点的starting/complete/failed结果。正式来源入口在CLI调用前登记，节点锁防并发重复提交；失败或中断结果未知时后续读取报告KNOWLEDGE_SHEET_EXPORT_PENDING_RESOLUTION，不再自动调用sheet export，不猜jobId、不用revision当完整正文快照，不降级CSV或跟随媒体src。Sheet目前没有独立续查命令，只有经原因处理后才能决定正式恢复动作。成功导出的当前完整xlsx仍正常安全扫描和解析，账本不是缓存或权限证据；后续真正新的成功来源读取仍下载当前正文。

目前migration018只应用验收15432。两份已证实internal/code5的历史失败已导入并验证guard，未提交导出或写索引；其他历史TLS/未知阶段的导出失败尚需根据实际阶段审计是否存在未明任务，不能据此宣称已可全量重启。已有失败不会因解析器/源元信息变化自动解除；没有自动清除或重试入口。真实PG测试使用fixture回调，不冒充真实DWS导出恢复。
