# A2UI Thinking 任务卡

任务卡 JSON 骨架不依赖预发布的模板 ID。**当前机器人投递尚未接通，`DINGTALK_A2UI_TASK_CARDS=false` 默认关闭**，原会话回复继续由机器人发送。个人 DWS A2UI 发送不得替代 Agent 响应。

宿主在任务受理时创建一张卡，随后更新同一个 `bizId` 和 `surfaceId`。固定骨架包含默认折叠的 `CollapsiblePanel`（`variant: reasoning`）及独立的结果区域。运行时标题为 `Thinking · 当前活动`；展开后显示已完成、未完成及正在执行的工具摘要。完成、失败、取消时关闭动态文字效果并显示最终状态。等待确认或澄清时保留卡片，待用户响应后继续任务。

摘要来自真实工具事件和面向用户的进度说明，不读取 reasoning 事件、原始命令、工具参数或内部思维链。历史保留最近 60 个工具完成事件。机器人传输接通后由宿主自动维护；当前展示工具也明确返回 `A2UI_ROBOT_TRANSPORT_UNAVAILABLE`，不得自动发送个人卡片。

创建前运行 DWS 离线协议及引用闭包校验。业务调用显式绑定发起用户身份，发送到原会话。创建和更新使用持久化幂等记录；未知投递结果不重放同一次写入。更新按任务串行，迟到进度不能覆盖取消、终态或等待确认状态。卡片不可用或最终更新失败时，结果回到原会话文字消息。

旧模板配置仍用于现有确认/授权卡。`shimmer` 当前仅 iOS 支持，是文字扫光，不能代替加载图标。JSON 草稿增加独立 Markdown 的 `[AIGenerating]` 宿主动画约定，运行时显示，等待/终态隐藏。它的客户端渲染尚未验证，不宣称已复现截图效果。

真实测试曾用个人 DWS 创建并更新卡片，暴露发送者身份错误，不能作为机器人 A2UI 验收通过。已关闭这一错误路径，并要求任务卡只能使用显式声明 `identity: robot` 的宿主传输实现。DWS v1.0.63 当前 leaf Schema 和官方实现仅提供个人 MCP 发送目标与消息参数，没有机器人身份或 `robotCode` 参数。这是当前 CLI 路径的限制，不证明 A2UI 协议本身无法由机器人投递。现有公开 SDK 的模板机器人投递不能被假定为无模板 JSON 入口。

验证：构建、生命周期及编排集成测试，覆盖身份与原会话、重启去重、串行终态更新、取消/等待状态、未知结果不重试，以及 reasoning/命令数据不进入用户卡片。JSON 骨架通过 DWS v1.0.63 的 `aicard lint --preflight new-card --emit`。
