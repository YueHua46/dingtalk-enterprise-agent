# 模块 7：纯代码校验与交付约束

入口 `validateListingDraft(draft, prepared, factBook, plan, rules, policy)` 为纯代码函数，无模型、工具、网络或写入接口。配置加载单独通过 `loadValidationPolicy(path)` 完成，路径由宿主选择。`validateListingGeneration` 另核对模块 6 回执的文案哈希、事实/规划/规则版本和会话身份，拒绝草稿被改动后复用旧回执。后续修订要产生新版本并重新校验。

## 校验内容

- 重新从当前任务资料建立事实表并逐项比较；篡改原值、出处、状态或原始资料不能凭有效 factId 通过。同用户、请求、会话和规则范围也必须一致。
- 严格结构、非空字段、可用事实 ID、重复/重叠引用、UTF-16 短语范围及 Unicode 代理对边界。引用之间的未知文字也按未标注声明拦截，不靠模型声称“这是非事实性营销句”。
- 模块 3 的 Unicode 字符长度、UTF-8 字节长度、严格/包含边界、五点条数、禁词短语、特殊字符和重复词；限制、例外及禁词均读取配置。规则待核实或需要人工判断时输出独立状态，绝不把它算作已证明平台合规。
- 标题字符的品牌例外只适用于本品资料的完整品牌名称；页面未核实品牌、部分子串和品牌外追加的禁字符不豁免。
- 五点重复文案及搜索词重复提醒。重复检查字段放在内部策略配置中，不声称是所有类目的平台禁令。

## 非数字声明和限定条件

`config/listing-validation.json` 是有来源、日期、版本和待核实标记的内部受控表达策略，不是 Amazon 官方规则。词表按 **完整原值 + 属性** 匹配，例如原文“支持 microSD 卡，卡需另购”只支持包含“card sold separately”的完整表达。只引用存储事实却写防水、彩色夜视、免费订阅或包含存储卡，都不能获得受控支持。

代码必须完整消费声明文本；允许的连接符限于配置中的标点、空格和 and，不能仅在长句里找到若干看起来正确的子串就通过。品牌/型号直接引用仅用于标题。该保守词表会拒绝许多意思可能正确但尚未登记的英文改写，列为 unsupported_expression 核实项，不用另一个模型判断其真伪，也不因“看着合理”自动通过。

当前词表覆盖样例摄像头的室内类型、2K/4K、网络限制、供电、红外夜视、存储/订阅费用、室内安装及包装排除项。不自动补充摄像头防护、兼容性、认证或未知规格。新产品有新参数/表达时，需要补充可信完整资料与宿主受控策略，而不是让模型修改规则。内部词表当前标记待核实，报告始终明确其范围限制。

## 数字和单位

数量表达必须带对应属性标签，如 `Weight: 0.35 kg`。使用模块 2 的精确十进制/BigInt 标准化，不用浮点相等判断；可识别 350 g 与 0.35 kg 的等价，但不能把重量移到续航，也不能把 up to、range、approximately 偷换成 exact。条件必须和原始数量条件一致；跨语言条件未登记时不能自动视为等价。

受控非数量表达（例如完整网络限制、2K 或型号）仍绑定其自身属性和完整原值；声明中出现资料没有的数字会被拦截。相同数字并不证明语义相同。未知单位、自由数字短语、未登记的认证和混合表达明确待核实，不猜测换算或补参数。数字支持必须同时满足属性、表达及限定条件检查。

## 结果与导出

结果有 invalid / blocked / needs_verification / checked 四种状态，同时给出逐字段 copyable 标记：任何硬错误或该字段的待核实问题都会阻止进入可直接复制的最终区。其他正确字段可以保留用于对比，任务级问题会明确标注；任务来源不可信或资料冲突时所有字段阻止复制。模块 9 必须消费此结果，不能只看 codeChecksPassed 就导出最终稿。

codeChecksPassed 仅表示已配置的确定性硬检查没有错误。受控表达、规则待核实、页面未核实、人工判断和模型核实项均独立记录。当前配置规则仍待核实，因此真实任务不会被伪装成整体校验通过，也不设置审批人或审批按钮。platformCompliance 始终为 not_established，checked 也不是 Amazon 官方认可或可直接上传凭证。

报告分别输出事实性声明计数、有效出处覆盖率和受控支持覆盖率。未标注文字按额外声明缺口计入分母，防止仅给一小段引用就得到 100%；无声明时覆盖率为 null（不适用）。出处覆盖率不等于事实支持覆盖率。无有效结构或生成失败不能记作校验通过。程序只检测声明范围，不能声称精确识别了所有自然语言事实。

## 验收和样例

运行 `npm test -- tests/listing-validation.test.ts` 与 `npm run build`。测试中的已核实策略与隔离规则只为验证代码分支，不能作为真实平台规则证据。

运行 `node scripts/listing-validation-smoke.mjs`：纯本地回放模块 6 固定 mock 与真实模型记录，保存 examples/listing/validation-sample.json 和 output/listing/validation-smoke.json。不会再次调用模型、DWS 或发送消息。真实模型记录缺失时只跳过该回放，明确显示 no_recording，不能称为真实验收通过。

模块 8 的修订与重新校验已实现，见 `docs/listing-module-8.md`。模块 9–10 尚未实现；最终 Word/Excel 和完整评估/动态工具接入待后续完成。
